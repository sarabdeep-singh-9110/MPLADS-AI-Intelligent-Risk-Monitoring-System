❓ Anticipated Jury Questions & Winning Answers
Click any question to view the winning technical answer
Q1: Why use unsupervised Isolation Forest instead of supervised XGBoost or Random Forest? +
Winning Answer: "Public scheme data lacks labeled historical 'fraud' datasets. Supervised learning requires thousands of confirmed fraud labels, which introduces severe confirmation bias. Isolation Forest is an unsupervised algorithm specifically engineered for anomaly detection by isolating rare, anomalous data points in high-dimensional space without requiring labeled ground truth."
Q2: How does the system handle unstandardized text in raw expenditure vouchers? +
Winning Answer: "We engineered a scoped fuzzy matching algorithm that constrains the candidate search space within the same State and Parliamentary Constituency. It computes token-overlap and SequenceMatcher similarity against sanctioned project titles, routing low-confidence matches to the Human-in-the-Loop review queue for verification."
Q3: Does a high risk score mean that a Member of Parliament is corrupt? +
Winning Answer: "Absolutely not. As enforced by statutory disclaimers across our UI, risk scores indicate statistical, temporal, or administrative divergence—such as prolonged unsanctioned duration or complex hospital allocations. The system exists purely to provide data-driven prioritization for where District Collectors should allocate limited physical inspection teams first."
Q4: How scalable is this architecture for Pan-India deployment across all ministries? +
Winning Answer: "The backend is built with indexed database queries, paginated REST streams, and decoupled ML inference. The entire dataset of 56,138 works and 143,256 vouchers loads in sub-50ms latency. The same schema and dual-engine architecture can be extended to PMGSY, MGNREGA, or Smart Cities schemes seamlessly."
